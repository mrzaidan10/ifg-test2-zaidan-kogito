Kogito Checkout Service
Name: Muhammad Rifqi Zaidan

A workflow-based checkout orchestration service built with Java 17, Quarkus, and Red Hat Kogito (jBPM/Drools).

The application implements a business process workflow (BPMN 2.0) to handle an e-commerce checkout pipeline—validating carts, checking inventory, processing payments, and finalizing orders.

What This Application Does
Processing flow:

REST API Request → Kogito Engine → Validate Cart → Check Inventory → Process Payment → Create Order / Reject

The application:

Exposes automatic REST endpoints generated by Kogito based on the BPMN process ID (/Process_Checkout)

Orchestrates conditional branching (gateways) based on cart validity, stock availability, and payment status

Binds incoming JSON payloads directly to custom Java data models (CheckoutRequest) via Kogito process variables and data mappings

Automatically handles state transitions and process instance execution out-of-the-box

Tech Stack
Java 17

Quarkus 3.x / Kogito 10.x (Drools & jBPM engine)

RESTEasy / Jackson (JSON binding)

Maven

Prerequisites
Make sure the following are available:

Java 17

Maven 3.9+

Quick Start
Clone or open the project directory in your terminal.

Run the application in Quarkus development mode:

Bash
mvn quarkus:dev
The application will start on http://localhost:8080.

Trigger the process via the built-in Kogito REST endpoint using curl:

Bash
curl -i -X POST http://localhost:8080/Process_Checkout \
-H "Content-Type: application/json" \
-d '{"request": {"cartId": "CART-001", "customerId": "USER-123", "amount": 150000, "cartValid": true, "stockAvailable": true, "paymentSuccessful": true, "orderId": "ORD-001"}}'
Input Payload Format
The incoming JSON payload must wrap the request object matching the CheckoutRequest data type configured in the BPMN start event data mapping:

JSON
{
  "request": {
    "cartId": "CART-001",
    "customerId": "USER-123",
    "amount": 150000,
    "cartValid": true,
    "stockAvailable": true,
    "paymentSuccessful": true,
    "orderId": "ORD-001"
  }
}
Output
Returns a 201 Created or process execution response containing the generated process instance ID (id), current status, and execution metadata.

Evaluates routing gateways dynamically based on the boolean flags inside the request payload (cartValid, stockAvailable, paymentSuccessful).
